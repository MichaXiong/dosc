# 如何补充章节 & 导出说明

## 架构

```text
unity3d-learning-outline.html   ← 大纲导航 + 阅读 + 导出
unity-content/
  P{x.y}.md                     ← 【正文唯一源】
  _sync_topics.py               ← P*.md → topics-data.js
  topics-data.js                ← 自动生成，勿手改
  HOW-TO-EXTEND.md              ← 本说明
```

## 内容定位（重要）

左侧 HTML 是**大纲导航**；点开的 `P*.md` 是**知识讲义**，不是作业手册。

| 要写 | 不要写 |
|------|--------|
| 概念、原理、为何这样设计 | 「练习 1/2/3」「作业」「验收标准」 |
| 基础用法 + **常用进阶** | 「检查清单」打卡题 |
| 关键 API / 参数 / 选型对比 | 里程碑式闯关任务 |
| 简短可运行示例（服务讲解） | 大段「按步骤交作业」流程 |
| 常见误区 / 性能与工程注意 | 「下一步去学哪一课」课程腔 |

### 正文建议结构

```markdown
# P{x.y} 标题

> 一句话定位（阶段 / 前置依赖）

## 概念与定位
## 基础用法（必要知识）
## 常用进阶
## 示例（服务于理解）
## 常见误区
## 面试题
## 相关章节（可选，一句话链接即可）
```

### 面试题要求（每节必有）

- 放在文末「常见误区」之后；**每节 3～6 题**
- 紧扣本节知识点（基础概念 + 常用进阶/对比/排坑）
- 每题结构统一：

```markdown
## 面试题

### Q1. 题目……
**参考答案：**  
简明完整作答（可含要点列表或短代码），按面试口述密度写，避免作业口吻。

### Q2. …
**参考答案：**  
…
```

## 补充流程

1. 新建/重写 `unity-content/P{x.y}.md`
2. `python unity-content/_sync_topics.py`
3. 刷新 HTML

若一次要改写很多节、输出可能超限：助手应先改约定 + 尽量多的章节，并明确列出**尚未改写的编号**，提示下次继续。

## 导出 MD（HTML 顶栏）

| 按钮 | 结果 |
|------|------|
| **导出全部内容** | 一份 Markdown：总目录 + 六阶段完整大纲要点 + 各已补讲义正文（未补节保留要点并标注未补充） |
| 仅导出当前节 | 正在阅读的单节 `P{x.y}.md` |

「全部内容」不以「只导出已补讲义」为准，必须以**大纲全树**为主体。
