# P1.4 GameObject 与 Component 模型

> 阶段 P1 · Unity 场景对象的基本组成规则：容器、组件、Transform、层级与 Prefab。

## 概念与定位

场景中几乎所有可交互实体都是 **GameObject**：一个带名字与激活状态的容器。  
**能力来自 Component**——网格、碰撞、音频、你的脚本都是组件。  
每个物体必有且仅有一个 **Transform**（位置/旋转/缩放，以及父子关系）。

```text
Player（GameObject）
├── Transform              ← 不能删除
├── CharacterController
├── PlayerMotor（脚本）
└── AudioSource
```

脚本继承 `MonoBehaviour` 后也是组件，必须挂在物体上才存在；不要 `new` 一个 MonoBehaviour 当组件用。

---

## Transform（基础）

| Inspector | 含义 | 常用 API |
|-----------|------|----------|
| Position | 位置 | `position`（世界）/ `localPosition`（相对父） |
| Rotation | 旋转 | `rotation`（Quaternion）/ 欧拉角显示 |
| Scale | 缩放 | `localScale` |

### 世界空间 vs 本地空间

- **世界**：相对场景原点  
- **本地**：相对父物体的原点与轴向；无父时本地≈世界  

```csharp
transform.position = new Vector3(0f, 1f, 0f);           // 世界
transform.localPosition = new Vector3(0f, 1f, 0f);      // 相对父
transform.Translate(Vector3.forward * d, Space.Self);   // 沿自身前方
transform.Translate(Vector3.forward * d, Space.World);  // 沿世界 Z
```

旋转在脚本里长期累加更推荐 `Quaternion`（`Rotate` / `LookAt` / `Slerp`），欧拉角适合显示与微调。非均匀缩放父物体再挂物理/动画子物体，容易出怪碰撞，尽量避免。

---

## 父子层级（基础）

子物体会随父物体的 TRS 变换；子物体 `localPosition` 可不变，世界位姿却在变。

典型用途：武器挂手上、座位下挂乘客、特效挂受击点。

```csharp
transform.SetParent(newParent, true);   // 保持世界位姿换父
transform.SetParent(newParent, false);  // 按本地坐标重新解释
```

`activeSelf` 是自身勾选；`activeInHierarchy` 要求自身及所有父级都启用。父关掉则子逻辑与渲染通常一并停。

---

## Prefab（基础 + 常用进阶）

Prefab 把物体（含子层级与组件参数）存成可复用资产。场景中的是**实例**，Project 里的是**资源**。

| 操作 | 效果 |
|------|------|
| 改资源 | 未覆盖的实例一起变 |
| 改实例 | 产生 Overrides，可 Apply 写回或 Revert 丢弃 |
| `Instantiate(prefab)` | 运行时生成 |

常用进阶点：

- 脚本与 Collider 尽量挂在 Prefab **根**上，方便查找与池化  
- 重复出现的互动物（敌人、子弹、拾取物）优先 Prefab；场景唯一的灯光/地形不必强行 Prefab  
- 嵌套 Prefab、Prefab Variant 用于「基类皮肤/难度差」，细节见资源工作流章节  

```csharp
[SerializeField] GameObject _coinPrefab;
void Spawn(Vector3 pos) => Instantiate(_coinPrefab, pos, Quaternion.identity);
```

---

## 组件启用与物体启用

- 关 **GameObject**：整棵子树退出层级活跃状态  
- 关 **Component**：只停该能力（如暂时禁用某脚本）  
- `GetComponent` 默认只找本物体；子/父链查找用 `GetComponentInChildren` / `InParent`（P2.4）

---

## 常见误区

- 以为改 `localPosition` 与 `position` 总等价（有父物体时不等）  
- 用 `transform.Find` 满天飞代替 Inspector 引用（易碎）  
- 只拷 Prefab 文件忘记 `.meta`，实例引用全粉  
- Play 模式里改的参数退出后丢失，却以为场景已保存

## 面试题

### Q1. GameObject 和 Component 是什么关系？Transform 有什么特殊之处？
**参考答案：**  
GameObject 是容器（名字、激活状态、层级位置）；真正能力来自挂载的 Component（渲染、碰撞、脚本等）。每个 GameObject **必有且仅有一个 Transform**，负责位置/旋转/缩放与父子关系，且不能删除。脚本作为 `MonoBehaviour` 也是组件，必须挂在物体上，不能靠 `new` 当组件用。

### Q2. `position` 和 `localPosition` 有什么区别？
**参考答案：**  
`position` 是世界坐标；`localPosition` 是相对父物体的本地坐标。无父物体时二者接近；有父物体时父级一动，子物体世界坐标会变，但 local 可以不变。移动 API 还要分清 `Space.Self` 与 `Space.World`。

### Q3. `SetParent(parent, worldPositionStays)` 第二个参数有什么用？
**参考答案：**  
`worldPositionStays == true`：换父时尽量保持世界位姿不变（常用于运行时拾取、挂载）。`false`：按本地坐标重新解释，容易「瞬移」到父物体局部原点附近的默认本地位姿。上车、拔刀挂点等场景要刻意选择。

### Q4. Prefab 资源与场景中的实例有什么区别？Overrides 是什么？
**参考答案：**  
Project 里的 Prefab 是模板资源；场景里是实例。改资源会影响未覆盖的实例；只改实例会产生 **Overrides**。Apply 写回模板，Revert 丢弃覆盖。运行时用 `Instantiate` 生成的也是实例。协作时重复物体应优先 Prefab，避免场景里复制粘贴多份难维护。
