# P2.1 语法速览与 MonoBehaviour

> 阶段 P2 · Unity 脚本以 `MonoBehaviour` 为组件载体；生命周期决定逻辑写在哪一帧、哪一阶段。

## 概念与定位

挂到物体上的 C# 脚本通常继承 `MonoBehaviour`。类名必须与文件名一致才能作为组件添加。引擎按固定规则调用 `Awake`、`Start`、`Update` 等消息方法——**不是**你在别处手动调用的普通函数。

---

## 语法要点（Unity 语境）

**字段**：存数据；`public` 或 `[SerializeField] private` 可出现在 Inspector（细节 P2.2）。  
**属性**：`get/set` 封装，默认不进 Inspector。  
**方法**：自写逻辑需自行调用，或绑到 UI/动画事件；生命周期方法由引擎调用。

```csharp
using UnityEngine;

public class PlayerMotor : MonoBehaviour
{
    [SerializeField] float _speed = 5f;

    void Update()
    {
        // 每帧
    }
}
```

访问修饰符够用即可：`public` / `private` / `protected`。组件间通信优先拖引用或明确 API，少用到处 `Find`。

---

## 生命周期（基础）

典型顺序（同一物体、组件启用时）：

```text
Awake → OnEnable → Start →（Update / FixedUpdate / LateUpdate 循环）
禁用 → OnDisable
销毁 → OnDestroy
```

| 方法 | 时机与用途 |
|------|------------|
| **Awake** | 实例加载后通常只一次；拿本物体组件、初始化自身 |
| **OnEnable** | 每次启用；适合订阅事件 |
| **Start** | 首帧更新前；同批 Awake 已结束，适合依赖其它对象的开局逻辑 |
| **Update** | 每帧；输入、非物理移动、计时 |
| **FixedUpdate** | 固定物理步；刚体力/速度 |
| **LateUpdate** | 所有 Update 之后；相机跟拍 |
| **OnDisable** | 每次禁用；对称取消订阅 |
| **OnDestroy** | 销毁时；最终清理（取消订阅更常放 OnDisable） |

口诀：**Awake 管自己，Start 管与别人的协作（入门级）**。`OnEnable`/`OnDisable` 可多次；`Awake`/`Start` 通常一次（禁用再启用不会再次 Start）。

```csharp
Rigidbody _rb;
void Awake() => _rb = GetComponent<Rigidbody>();

void OnEnable()  => EventBus.OnPause += HandlePause;
void OnDisable() => EventBus.OnPause -= HandlePause;
```

---

## 常用进阶

- **执行顺序**：多脚本间可用 Script Execution Order 调整；更稳的是显式初始化流程，而非依赖隐式顺序。  
- **空 Update**：大量空 `Update` 仍有调度成本；不用就删。  
- **timeScale**：`WaitForSeconds` 与部分逻辑受暂停影响；UI 倒计时常用非缩放时间（见协程章节）。  
- **不要 new MonoBehaviour**；用 `AddComponent` 或 Prefab。  
- 动态 `Instantiate` 出的对象，其 Awake 在创建当帧就会走，不要假设「下一帧才初始化」。

---

## 常见误区

- 在 Awake 里假定别的物体已经 Start 完  
- 物理写在 Update 里硬改 `transform`，与 Rigidbody 打架  
- 只在 OnDestroy 取消事件，物体禁用未销毁时仍被回调  
- 类名与文件名不一致导致无法挂载

## 面试题

### Q1. `Awake`、`OnEnable`、`Start` 的调用顺序和各自适合做什么？
**参考答案：**  
典型顺序：`Awake` → `OnEnable` → `Start`。`Awake` 通常只一次，适合拿本物体组件、初始化自身；`OnEnable` 每次启用都可能调用，适合订阅事件；`Start` 在首帧更新前，且同批对象 Awake 已结束，适合依赖其他对象的开局逻辑。禁用再启用一般不会再次 `Awake`/`Start`，但会再走 `OnEnable`。

### Q2. `Update`、`FixedUpdate`、`LateUpdate` 如何分工？
**参考答案：**  
`Update`：每帧，输入与非物理逻辑。`FixedUpdate`：固定物理时间步，刚体力/速度。`LateUpdate`：所有 Update 之后，适合相机跟拍。物理相关不要在 Update 里硬改带 Rigidbody 的 `transform` 与物理引擎抢控制权。

### Q3. 为什么事件订阅常在 `OnEnable`，取消订阅在 `OnDisable`，而不是只写在 `OnDestroy`？
**参考答案：**  
物体可能被反复启用/禁用而未销毁。只在 `OnDestroy` 取消，禁用期间仍可能被事件回调，导致空引用或逻辑错误。`OnEnable`/`OnDisable` 成对更对称；销毁前通常也会先 Disable。

### Q4. 为什么不能 `new MonoBehaviour`？类名与文件名不一致会怎样？
**参考答案：**  
组件必须挂在 GameObject 上，由引擎管理生命周期，应使用 `AddComponent` 或 Prefab。类名与文件名不一致时，脚本无法正确作为组件添加，Inspector 会表现为无法挂载或丢失脚本。
