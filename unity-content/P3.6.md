# P3.6 角色控制链路：移动 · 相机 · Trigger 交互

> 阶段 P3 · 把碰撞触发、角色移动、相机跟拍收成一条可运行的知识链路（侧重机制，而非项目作业）。

## 概念与定位

可玩角色场景的最小闭环是三条线并行：

```text
输入 → Motor（Update / CC.Move）→ 角色位姿
输入 → Camera（LateUpdate）    → 机位
位姿变化 → Trigger 重叠        → OnTriggerEnter → 拾取/伤害/区域逻辑
```

理解「谁在哪一帧写位置、谁只读位置、消息挂在谁身上」，比堆 Prefab 数量更重要。

---

## 链路一：移动（回顾要点）

- 人形默认 **CharacterController + 自管重力/跳跃**（P3.4）  
- 水平速度与 `velocity.y` 合成后 `Move`  
- 相对相机方向时抹平 forward/right 的 Y  
- 接地判断以 Move 后的 `isGrounded` 为准，必要时 SphereCast 辅助  

---

## 链路二：相机（回顾要点）

- Pivot 轨道 + 距离；穿墙 SphereCast 缩短臂长（P3.5）  
- **LateUpdate** 跟拍  
- 与 Motor 约定：移动读相机水平朝向，相机读角色位置  

两者抢同一 `transform` 或都放 Update，是抖动与不同步的常见来源。

---

## 链路三：Trigger 交互（基础）

触发器：Collider 勾选 **Is Trigger**，不产生物理阻挡，只产生回调。

| 回调 | 含义 |
|------|------|
| `OnTriggerEnter` | 进入 |
| `OnTriggerStay` | 停留（每物理帧，慎做重逻辑） |
| `OnTriggerExit` | 离开 |

**消息接收者**须是：带 Rigidbody 的物体，或带 **CharacterController** 的物体（CC 可充当「能动的一方」）。脚本应挂在能收到消息的对象上（通常是 Player 根节点与 CC 同物体）。

```csharp
void OnTriggerEnter(Collider other)
{
    if (!other.CompareTag("Pickup")) return;
    var item = other.GetComponent<PickupItem>()
            ?? other.GetComponentInParent<PickupItem>();
    if (item == null) return;
    // 加分、播放反馈、item.Collect() → Destroy 或回池
}
```

拾取物侧：Trigger Collider + 逻辑组件（分值、回池、特效引用）。Tag/Layer 用于过滤；Layer Collision Matrix 关掉则永不相交。

---

## 常用进阶

### 交互过滤

- Tag 粗分：`Pickup` / `Checkpoint` / `Damage`  
- Layer 做物理矩阵级过滤，比在回调里写大量 if 更干净  
- 用接口（如 `IInteractable`）统一 `OnInteract(player)`，避免每个 Trigger 一套硬编码  

### 与物理碰撞的分工

- 墙、地面：非 Trigger，挡住 CC/刚体  
- 金币、毒区、风速区：Trigger，只发事件  
- 需要「先碰到再判定」时注意静态 Trigger + 静态无 RB 物体可能不触发——保证一方「可动」或带 RB/CC  

### 传送与 CC

改 `transform.position` 传送前常先 `cc.enabled = false`，到位后再开，避免内部重叠状态异常。

### 反馈

计数可读组件属性供 UI（P4）；音效/粒子在 Collect 时生成（P6.2）；不要在 `OnTriggerStay` 里每帧 Instantiate。

---

## 机制串起来的数据流

```text
PlayerMotor.Move
    ↓
Player 进入金币 Trigger
    ↓
PlayerPickup.OnTriggerEnter
    ↓
PickupItem.Collect → Destroy/池化
    ↓
Count++ → UI 绑定或事件总线通知
```

相机不参与拾取；拾取不改 CC 参数。保持模块单向依赖，后续加动画/UI 才不会缠死。

---

## 常见误区

- 拾取物忘了 Is Trigger，变成物理顶开  
- 脚本挂在无 CC/RB 的子物体上收不到 Enter  
- Stay 里做重逻辑导致卡顿  
- 相机 Simulation/跟拍与 Motor 帧不同步却去「调感」浪费时间

## 面试题

### Q1. 做一个可玩角色场景，移动、相机、拾取三条线应如何分工到帧与组件？
**参考答案：**  
移动（Motor）在 `Update`/`Move` 写角色位姿；相机在 `LateUpdate` 读位姿跟拍；拾取通过 Trigger 回调响应重叠，不负责每帧改机位。避免多个系统同帧抢同一 Transform，也避免在 `OnTriggerStay` 里做重逻辑。

### Q2. Trigger 与普通 Collider 有何区别？`OnTriggerEnter` 要挂在什么对象上才能收到？
**参考答案：**  
Is Trigger 的碰撞体不产生阻挡，只产生触发回调。要收到消息，参与方中通常需要有一方带 **Rigidbody**，或带 **CharacterController**（可作为能动方）。脚本应挂在能收到消息的对象上（常见是与 CC 同物体的 Player 根）。双方都静态且无 RB/CC 时可能不触发。

### Q3. 为什么用 CharacterController 传送位置前常常先禁用再启用 CC？
**参考答案：**  
直接改 `transform.position` 可能让 CC 内部重叠状态异常。传送时先 `enabled = false`，设位置后再 `true`，是常见稳妥写法，减少卡墙/弹飞。

### Q4. Tag、Layer、脚本接口在交互过滤上如何分工？
**参考答案：**  
Tag 适合粗分类（Pickup/Damage）；Layer + Collision Matrix 在物理层过滤，减少无用回调；接口（如 `IInteractable`）统一交互入口，避免每个 Trigger 一套硬编码。正式项目三者常组合使用。
