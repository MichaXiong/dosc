# P4.1 uGUI 基础

> 阶段 P4 · Unity 内置 **uGUI**（`UnityEngine.UI` + Canvas 体系）。与 3D 的 `Transform` 平行，但是 **矩形锚点布局 + 屏幕/世界画布渲染 + 事件射线点击**。本节把 Canvas、Scaler、RectTransform、常用控件与事件链路讲透。

## 概念与定位

uGUI 可以概括成四层：

```text
EventSystem          ← 谁在点、点到了谁
Canvas + Scaler      ← 画在哪、怎么随分辨率缩放
RectTransform 树     ← 矩形怎么锚、怎么排
Graphic 控件         ← Image / Text / Button… 画什么、能不能点
```

要点：

- 所有可见 UI 都必须在某个 **Canvas** 下。  
- UI 节点用 **RectTransform**（不是普通 Transform 的思维）。  
- 没有 **EventSystem**（以及匹配的 Input Module），按钮点不动。  
- 新项目文本优先 **TextMeshPro**；老项目仍常见 Legacy `Text`。  
- **UI Toolkit** 是另一套 UI 技术，API 与工作流不同；手游/项目存量仍以 uGUI 为主，本节只讲 uGUI。

和 3D 的分工：HUD/菜单 → Overlay/Camera Canvas；场景里的终端屏、漂浮名牌 → World Space Canvas，或「世界坐标转屏幕坐标 + Overlay 跟随」（P3.5 飞向 UI 同理）。

## 1. Canvas：画布怎么画到屏幕上

### 1.1 创建与默认组件

Hierarchy → **UI → Canvas**，通常自动带上：

| 组件 | 作用 |
|------|------|
| Canvas | 渲染模式、相机、排序 |
| Canvas Scaler | 分辨率适配 |
| Graphic Raycaster | UI 点击射线检测 |

同时场景会出现 **EventSystem**（全局一份即可）。

### 1.2 Render Mode 详解

| 模式 | 机制 | 优点 | 注意 |
|------|------|------|------|
| **Screen Space - Overlay** | 直接画在屏幕最前，不经过游戏相机 | 简单、清晰、最常用 | 不受相机 FOV/后处理影响；与 3D 深度排序能力弱 |
| **Screen Space - Camera** | 在指定相机前方一张「屏幕平面」上画，可设 Plane Distance | 可进相机栈、可与 3D 穿插排序 | 必须指定 **Render Camera**；FOV/距离会影响观感 |
| **World Space** | Canvas 是场景里的四边形 | 世界看板、舱内屏 | 要设尺寸与事件相机；近大远小；注意分辨率与文字清晰度 |

**坐标换算（高频）：**

```csharp
// Overlay：cam 传 null
RectTransformUtility.ScreenPointToLocalPointInRectangle(
    parentRect, screenPos, null, out var local);

// Screen Space - Camera / 需要事件相机时：
RectTransformUtility.ScreenPointToLocalPointInRectangle(
    parentRect, screenPos, canvas.worldCamera, out local);
```

世界坐标 → 屏幕点：`RectTransformUtility.WorldToScreenPoint(cam, worldPos)` 或 `camera.WorldToScreenPoint`。

### 1.3 多 Canvas 与排序

- 同一 Render Mode 下，用 Canvas 的 **Sort Order**（或 Sorting Layer + Order）控制谁画在上面。  
- 常见拆分：**HUD Canvas**（常驻）与 **Popup Canvas**（弹窗，Order 更高），避免整棵 HUD 因弹窗频繁重建。  
- Camera/World 模式还要和 3D 的 Sorting Layer、相机深度一起考虑。  
- Overlay 永远在普通 3D 相机画面「之上」（不经该相机），后处理一般吃不到 Overlay UI（要后处理 UI 需特殊方案或 Camera 模式）。

### 1.4 Pixel Perfect 与附加选项

- **Pixel Perfect**：尽量对齐像素格，减轻文字/细线发糊；开启后动态动画可能略「一格一格」。  
- **Additional Shader Channels**：TMP、法线类特效需要时再开，乱开会增加负担。  
- Canvas 可挂 **Canvas Group**：统一改 Alpha、Interactable、Blocks Raycasts（整页淡入淡出、禁用交互很常用）。

## 2. Canvas Scaler：分辨率适配

不同设备分辨率/宽高比下，UI 不能写死像素位置完事。Scaler 决定「设计稿」如何映射到真机。

### 2.1 三种 Scale Mode

| UI Scale Mode | 行为 | 何时用 |
|---------------|------|--------|
| Constant Pixel Size | 控件像素尺寸基本固定 | 极简单工具界面；或你完全自己算缩放 |
| **Scale With Screen Size** | 相对参考分辨率整体缩放 | **默认推荐**，绝大多数游戏 HUD |
| Constant Physical Size | 按物理 DPI | 少见 |

### 2.2 Scale With Screen Size 核心参数

- **Reference Resolution**：设计基准，如 `1920 × 1080` 或 `1080 × 1920`（竖屏）。全组必须统一。  
- **Screen Match Mode**  
  - Match Width Or Height（最常用）  
  - Expand / Shrink（按较长/较短边策略）  
- **Match**（0~1）：0 更跟宽度，1 更跟高度，0.5 折中。  

**直觉：**

- 横屏 16:9 设计，到 18:9 / 21:9 超宽屏：Match 偏高度（靠近 1）可减少上下被裁，左右留白或扩展。  
- 竖屏游戏相反，常偏宽度。  
- 没有银弹：要在目标机型上目视验收安全区、刘海、底栏。

### 2.3 与锚点的关系（重要）

Scaler 负责「整棵 Canvas 的缩放系数」；**锚点**负责「父矩形变化时子控件贴哪」。  
二者要一起设计：先定参考分辨率与 Match，再定四角/四边锚点。先乱摆 Absolute 像素、后期再改 Scaler，返工巨大。

### 2.4 Safe Area（常用进阶）

刘海屏/挖孔屏：用 `Screen.safeArea` 把 HUD 根节点限制在安全区内（运行时改锚点或边距）。可做独立 `SafeAreaFitter` 组件挂在 HUD 根上。逻辑要点是：把 safeArea 从屏幕像素转到 Canvas 本地，再设 `offsetMin/offsetMax` 或 anchor。

## 3. RectTransform：锚点布局核心

UI 每个节点都是矩形。RectTransform 在 Transform 之上增加了锚点与矩形尺寸语义。

### 3.1 字段对照

| 概念 | 含义 |
|------|------|
| **anchorMin / anchorMax** | 父矩形上的归一化锚点（0~1）。两点重合=钉在一点；拉开=相对父边拉伸 |
| **pivot** | 自身轴心（0~1），旋转/缩放/部分布局绕它 |
| **anchoredPosition** | 相对锚点的偏移（锚点为点时最直观） |
| **sizeDelta** | 相对锚点矩形的尺寸增量；锚点重合时≈宽高 |
| **offsetMin / offsetMax** | 拉伸锚点时的左下/右上边距（Inspector 里 Left/Bottom/Right/Top） |

Inspector 左上角锚点预设（Alt/Shift 组合）可同时设锚点与位置，务必熟练。

### 3.2 三种典型锚法

1. **固定尺寸 + 角落/中心锚点**  
   按钮、图标。父变大时贴角或居中，自身宽高不变。  
2. **左右/上下拉伸**  
   顶栏全宽、侧栏全高。锚点拉成一条边或对边，用边距控制厚度。  
3. **四边拉伸（stretch-stretch）**  
   全屏面板、背景。Left/Right/Top/Bottom 表示距父边的 padding。

```csharp
var rt = (RectTransform)transform;

// 钉在父级左上，向下向右延伸固定大小
rt.anchorMin = new Vector2(0f, 1f);
rt.anchorMax = new Vector2(0f, 1f);
rt.pivot = new Vector2(0f, 1f);
rt.anchoredPosition = new Vector2(20f, -20f);
rt.sizeDelta = new Vector2(320f, 80f);

// 四边拉伸，距父 10px 边距
rt.anchorMin = Vector2.zero;
rt.anchorMax = Vector3.one; // 写成 Vector2.one
rt.offsetMin = new Vector2(10f, 10f);   // left, bottom
rt.offsetMax = new Vector2(-10f, -10f); // -right, -top
```

### 3.3 父子与「百分比布局」

锚点本质是相对父 **Rect** 的百分比挂靠。父是全屏 Canvas 还是某个 Panel，结果完全不同。  
做自适应弹窗：背景四边拉伸，内容区再套 Vertical Layout。

### 3.4 代码改布局后的刷新

改完子项尺寸/激活状态，有时列表不立刻重排：

```csharp
LayoutRebuilder.ForceRebuildLayoutImmediate(parentRect);
```

或下一帧再读 `rect.width`（布局可能延迟一帧计算完）。

### 3.5 Layout 组件（常用进阶）

| 组件 | 作用 |
|------|------|
| Horizontal / Vertical Layout Group | 按行/列自动排布子节点 |
| Grid Layout Group | 网格 |
| Content Size Fitter | 按首选尺寸撑开自身（常挂在 Content 上） |
| Layout Element | 覆盖子项 min/preferred/flexible |

注意：Layout Group 会驱动子 RectTransform，**子物体上再手改 anchoredPosition 易被覆盖**。列表项内部自己锚点布局，外部交给 Layout。

## 4. 常用控件详解

### 4.1 Image

- **Source Image**：Sprite；纯色可只设 Color。  
- **Image Type**：Simple / Sliced（九宫格，边框不拉伸）/ Tiled / **Filled**（圆图、血条进度）。  
- **Preserve Aspect**：保持宽高比。  
- **Raycast Target**：是否参与点击检测。装饰底图、粒子层 UI 建议关掉，减少误挡与开销。  
- 图集：Sprite Atlas 减少 Draw Call（合批还受材质、深度打断影响）。

Filled 血条：

```csharp
[SerializeField] Image _hpFill; // Image Type = Filled, Horizontal
public void SetHp(float normalized01) => _hpFill.fillAmount = Mathf.Clamp01(normalized01);
```

### 4.2 Text 与 TextMeshPro

| | Legacy Text | TextMeshPro |
|--|------------|------------|
| 清晰度 | 一般 | 更好（有向距离场） |
| 富文本/图集 | 弱 | 强 |
| 资源 | Font | TMP Font Asset（可建备用字库） |

常用点：Overflow（Truncate/Ellipsis）、Wrapping、Alignment、Color Gradient。  
慎用 **Best Fit**（每帧测字号，列表里贵且可能抖动）。  
改 `text` 极频繁时注意 GC（字符串拼接）；TMP 有 `SetText` 等重载可减少分配。

### 4.3 Button

- **Interactable**：总开关。  
- **Transition**：None / Color Tint / Sprite Swap / Animation。  
- 子节点通常有 Text；点击区域是 Button 所在 Graphic 的射线范围（可把透明 Image 拉大热区）。  

事件两种绑法：

```csharp
// 代码（推荐复杂逻辑）
void OnEnable()  => _btn.onClick.AddListener(OnClick);
void OnDisable() => _btn.onClick.RemoveListener(OnClick);
```

Inspector **OnClick()**：快，但重构易断、不能方便传复杂闭包。

### 4.4 Slider / Scrollbar

- Slider：`minValue`/`maxValue`/`wholeNumbers`/`value`，`onValueChanged`。  
方向 Horizontal/Vertical；可做音量、灵敏度、非 Filled 的进度。  
注意：代码里设 `value` 也会触发 `onValueChanged`，初始化时可能需要暂时移除监听或加「忽略回调」标志。

### 4.5 Toggle 与 ToggleGroup

- Toggle：`isOn` + `onValueChanged`。  
- ToggleGroup：组内互斥单选（设置页画质档等）。  
初始化赋值同样可能触发回调，注意时序。

### 4.6 InputField / TMP_InputField

- 文本输入、密码、多行。  
- 移动端：键盘顶起、焦点、提交事件 `onEndEdit` / `onSubmit`。  
- 校验放在提交或 `onValueChanged`（后者更频繁）。

### 4.7 Scroll Rect（列表）

结构通常为：

```text
Scroll View
├── Viewport（Mask / Rect Mask 2D）
│   └── Content（Vertical Layout + Content Size Fitter）
│       ├── Item
│       └── Item
└── Scrollbar（可选）
```

要点：Content 被撑高后才能滚；方向与 Movement Type（Elastic/Clamped）；大量条目不要无脑 Instantiate 上千个——用循环列表/对象池（进阶优化，面试常问）。

### 4.8 Dropdown、Panel、RawImage

- Dropdown / TMP_Dropdown：选项列表。  
- Panel：常是带 Image 的空容器，作底板。  
- RawImage：直接贴 Texture（非 Sprite），视频/RenderTexture 预览常用，合批不如 Sprite 友好。

## 5. 遮罩、画布组与特效向组件

### 5.1 Mask vs Rect Mask 2D

| | Mask | Rect Mask 2D |
|--|------|----------------|
| 原理 | 基于模板/父 Image 形状 | 矩形裁剪，一般更轻 |
| 形状 | 可用异形 Image | 仅矩形 |
| 建议 | 需要圆头像等异形时 | 列表 Viewport 优先 Rect Mask 2D |

嵌套 Mask 过多会增加 Overdraw 与合批难度。

### 5.2 Canvas Group

```csharp
[SerializeField] CanvasGroup _group;
_group.alpha = 0.5f;
_group.interactable = false;
_group.blocksRaycasts = false; // false 时点击穿透到下层
```

整页淡入、弹窗打开时锁下层 HUD，非常常用。

### 5.3 Outline / Shadow

挂在 Graphic 上的简易描边阴影，便宜但效果一般；品质要求高时用 TMP 材质或自定义。

## 6. EventSystem 与点击链路（常用进阶）

### 6.1 点击如何发生

1. 指针位置 → EventSystem  
2. GraphicRaycaster（UI）/ PhysicsRaycaster（3D）做射线  
3. 从上到下找可 Raycast 的 Graphic  
4. 派发 PointerClick 等 → Button 响应  

### 6.2 输入模块

- 旧 Input：Standalone Input Module  
- 新 Input System：需换 **Input System UI Input Module**，否则升级后全员点不动  

### 6.3 与玩法输入冲突

```csharp
if (EventSystem.current != null &&
    EventSystem.current.IsPointerOverGameObject())
{
    // 点在 UI 上：不要开火 / 不要走地面点选
    return;
}
```

触屏多指时重载参数要用对应 fingerId，细节依平台查询。

### 6.4 自定义可点击

实现 `IPointerClickHandler` 等接口，挂在带 Graphic（可 Raycast）的物体上，即可收事件，不必非用 Button。

```csharp
using UnityEngine.EventSystems;

public class ClickProxy : MonoBehaviour, IPointerClickHandler
{
    public void OnPointerClick(PointerEventData eventData) { /* ... */ }
}
```

## 7. 结构示例：HUD + 弹窗分层

```text
EventSystem

Canvas_HUD (Overlay, Sort 0, Scaler 1920x1080 Match 0.5)
└── SafeArea
    ├── TopBar（上边拉伸）
    │   ├── HpFill（Image Filled）
    │   └── CoinText（TMP）
    └── BottomSkill（下边锚点）

Canvas_Popup (Overlay, Sort 100)
└── MaskDim（全屏半透明 Image，挡下层）
    └── Dialog（居中固定尺寸）
        ├── Title
        ├── Body
        └── ButtonOK
```

弹窗层升 Order + 全屏挡射线，比把弹窗塞进 HUD 深处更清晰，也利于整页 Canvas Group 淡入。

## 8. 性能与工程注意（常用进阶）

| 点 | 说明 |
|----|------|
| 合批 | 同 Atlas、同材质、中间少打断（粒子/不同材质会打断） |
| Overdraw | 半透明大图多层叠最伤填充率；弹窗背后可藏 HUD |
| Raycast Target | 能关则关 |
| 重建 | 改层级/启用禁用会重建 Canvas；拆 Canvas、减少无意义脏标记 |
| 字符串 | 高频刷新分数用缓存或 StringBuilder/TMP SetText |
| 大列表 | 循环复用 Item，勿一次生成全部 |
| 世界空间 UI | 慎对每个单位一个 World Canvas；可改为屏幕空间跟随合并到一个 HUD |

## 9. 与世界交互的两种血条思路

1. **World Space Canvas** 挂在角色头顶：简单，单位多时贵。  
2. **Overlay 单 Canvas**：世界坐标转屏幕坐标，每帧设 `anchoredPosition`（或仅脏时更新）：单位多时更常见。

飞向 Screen Space UI 的金币动画同属「世界 → 屏幕 → Canvas 本地」转换问题。

## 常见误区

- 场景无 EventSystem / 输入模块与 Input System 不匹配 → 全员无法点击  
- Overlay 换算却传了 Camera，或 Camera 模式 cam 为 null → 坐标偏移  
- 参考分辨率与锚点混乱，换机型全盘错位  
- 全屏透明 Image 开着 Raycast，挡住所有按钮  
- 在 Layout Group 子项上死拧 Rect，运行时被布局刷掉  
- 多个 EventSystem  
- 用 `transform.position` 当 UI 布局主手段，忽略锚点（分辨率一变就崩）  
- Best Fit + 大列表导致卡顿  
- World Space Canvas 字发糊：尺寸/缩放/相机距离不匹配

## 面试题

### Q1. Canvas 三种 Render Mode 的区别与选型？
**参考答案：**  
**Overlay**：不经游戏相机直接叠屏，适合绝大多数 HUD/菜单，实现简单。**Screen Space - Camera**：渲染在指定相机前方平面，可参与相机相关排序/距离，适合要和 3D 有空间关系的 UI。**World Space**：Canvas 作为场景物体，适合舱内屏、世界看板。坐标转换时 Overlay 的 eventCamera 一般为 null，Camera 模式必须用正确的 `worldCamera`。

### Q2. Canvas Scaler 的 Reference Resolution 与 Match 如何影响适配？
**参考答案：**  
Scaler 在 Scale With Screen Size 下按参考分辨率计算缩放比。Match 在宽/高适配间插值：0 偏宽、1 偏高。超宽屏若仍强匹配宽度，UI 可能上下被裁或比例怪异。锚点解决「相对父矩形贴哪」，Scaler 解决「整体缩多少」，两者需一起设计。

### Q3. 解释 Anchors、Pivot、anchoredPosition、sizeDelta / offsetMin·Max。
**参考答案：**  
Anchors 是父 Rect 上的归一化挂靠点或挂靠矩形；Pivot 是自身轴心；anchoredPosition 是相对锚点的偏移；锚点重合时 sizeDelta 近似宽高，锚点拉伸时用 offsetMin/offsetMax（Left/Bottom/Right/Top）表边距。面试常问：全屏背景怎么锚、左上角血条怎么锚。

### Q4. 按钮点不到，你怎么排查？
**参考答案：**  
查 EventSystem 与 Input Module；查上层是否有 Raycast Target 的透明图；Canvas Group 是否关掉 interactable/blocksRaycasts；按钮 Interactable；Camera/World 模式事件相机；是否被更高 Sort Order 的全屏层挡住；用 EventSystem 当前选中信息辅助。触屏还要注意 IsPointerOverGameObject 的指尖 id。

### Q5. Mask 和 Rect Mask 2D 有何区别？列表 Viewport 怎么选？
**参考答案：**  
Mask 依赖父级遮罩图，可异形，开销相对大。Rect Mask 2D 做矩形裁剪，更轻，Scroll View 的 Viewport 优先用它。只有圆头像等异形裁剪才上 Mask。

### Q6. 为什么常把 HUD 和弹窗拆成两个 Canvas？Canvas 重建有什么影响？
**参考答案：**  
Canvas 在脏时会重建合批网格。弹窗频繁显隐若与巨大 HUD 同 Canvas，可能带动大范围重建。拆成 HUD（低 Order）与 Popup（高 Order）可隔离脏区域，并用全屏挡板阻止穿透点击。同时注意合批、Overdraw 与 Raycast 数量。

### Q7. Image.Filled、Slider、自定义网格进度条各适合什么？
**参考答案：**  
Filled 改 `fillAmount`，适合血条/圆CD，实现轻。Slider 带拖拽交互与句柄，适合设置项。极特殊形状或大量进度可用自定义 Mesh/Shader。初始化设值时注意 `onValueChanged` 被误触发。
