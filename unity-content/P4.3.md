# P4.3 Animation 与 Animator

> 阶段 P4 · Unity **Mecanim** 动画体系的主干：Animation Clip（动画数据）→ Animator Controller（状态机）→ Animator 组件（播放器）。本节把 Clip 制作、状态机、参数、Transition、Blend Tree 与脚本驱动讲透；Humanoid / Root Motion / Avatar Mask 等角色进阶见 **P4.4**。

## 概念与定位

可以把动画系统拆成三层：

```text
Animation Clip          ← 「一段动画长什么样」（曲线 / 骨骼采样）
Animator Controller     ← 「什么时候播哪段、怎么混合」（状态机 + 参数）
Animator（组件）         ← 挂在物体上，运行时真正播放与设参
```

| 概念 | 是什么 |
|------|--------|
| **Animation Clip** | 资产：某段时间内属性如何变化（Transform、骨骼、材质参数等） |
| **Animator Controller** | 资产：状态图、过渡条件、混合树、层 |
| **Animator** | 组件：引用 Controller，暴露 `SetFloat`/`SetTrigger` 等 |
| **旧 Animation 组件** | 更老的逐 Clip 播放 API，遗留项目可见；新做角色动画优先 Animator |

还有一条旁路：**Timeline** 做过场编排，最终也常驱动 Animator 或直接播 Clip；玩法状态机仍以 Animator Controller 为主。

和逻辑的关系：移动脚本（P3.4）算出 Speed / IsGrounded，**写参数进 Animator**；Animator 负责视觉，一般不要在动画状态里写玩法权威逻辑（可用 StateMachineBehaviour 做辅助，见后文）。

## 1. Animation Clip：动画数据从哪来

### 1.1 来源

| 来源 | 说明 |
|------|------|
| DCC 导出（FBX） | Maya/Blender 等；导入后在 Model 的 Animation 页看到 Clips |
| Unity 内录制 | Animation 窗口对物体属性打关键帧（道具、UI、简单机关） |
| 动画商店 / Mixamo 等 | 注意授权与 Avatar 类型（Generic / Humanoid） |
| 程序生成 | 少见；或运行时改曲线（进阶） |

FBX 导入器关键页：

- **Animation Type**：None / Legacy / Generic / Humanoid  
- **Avatar**：Humanoid 需映射骨骼；Generic 按层级路径  
- Clip 列表：起止帧、Loop Time、Root Transform 相关选项（Root Motion 细节 P4.4）  
- **Bake Animations**、压缩格式影响体积与精度  

### 1.2 在 Unity 里做简单 Clip（非骨骼）

1. 选中物体 → Window → Animation → Animation  
2. Create New Clip，保存到例如 `Art/Animations/`  
3. 对 Position/Rotation/Scale 或其它可动画属性 Add Property，在时间轴打关键帧  
4. 会自动生成 Animator（若无）并挂上含该 Clip 的 Controller  

适合：箱子开关、UI 弹出、风扇旋转。复杂角色仍用外部骨骼动画。

### 1.3 Clip 常用设置

在 Project 选中 Clip（或 FBX 子 Clip）：

| 项 | 含义 |
|----|------|
| Loop Time | 是否循环（Idle/Walk 通常开；Attack 通常关） |
| Loop Pose | 循环时首尾姿态混合，减轻脚滑突变 |
| Cycle Offset | 循环相位偏移 |
| Root Transform Position/Rotation | 是否烘焙进姿态、还是交给 Root Motion |
| Mirror | 左右镜像（部分情况） |
| Additive Reference Pose | 叠加层参考姿势 |

**事件（Animation Event）**：在某一帧调用脚本方法（出刀判定、脚步声）。帧事件绑在 Clip 上，函数签名需匹配；对象上要有接收方法的组件。滥用事件会让逻辑散落，关键玩法帧可用，但复杂技能更常在逻辑层计时或 StateMachineBehaviour。

### 1.4 曲线与采样

骨骼动画本质是每帧（或压缩后）的骨骼局部变换。导入压缩（Keyframe Reduction、Error 阈值）会减体积但可能抖脚；角色脚滑有时是压缩 + 根运动/位移脚本冲突，不全是美术问题。

## 2. Animator 组件与 Controller

### 2.1 挂接关系

```text
角色 GameObject
├── Animator
│     Controller → Player.controller
│     Avatar     → 人形 Avatar（Humanoid 时）
│     Apply Root Motion
│     Update Mode：Normal / Animate Physics / Unscaled Time
│     Culling Mode：Always Animate / Cull Update Transforms / Cull Completely
└── 模型子层级（SkinnedMeshRenderer + 骨骼）
```

- **Update Mode**  
  - Normal：跟帧更新（默认）  
  - Animate Physics：跟物理步（与刚体交互时）  
  - Unscaled Time：不受 `timeScale` 影响（暂停菜单里的 UI 动画可用）  
- **Culling**：镜头外是否仍算动画；移动端可 Cull 省 CPU，但要确保切回镜头时状态正确。  
- **Apply Root Motion**：勾选则由动画曲线驱动位移/旋转（P4.4）；与 CharacterController 脚本位移需约定谁说了算。

### 2.2 创建 Controller

Project 右键 → Create → Animator Controller，拖到 Animator.Controller。  
双击打开 **Animator 窗口**：图层、参数、状态机画布。

空 Controller 默认有 **Entry →（橙色默认状态）**。第一个拖进去的 Clip 常成为默认状态（可改）。

## 3. 状态机（State Machine）基础

### 3.1 节点类型

| 节点 | 作用 |
|------|------|
| **Entry** | 进入本层时的入口，连到默认状态 |
| **Exit** | 子状态机退出点（嵌套时） |
| **Any State** | 从「任意状态」可转入；适合受击、死亡，但易造成难控跳转，慎用 |
| **State** | 播一个 Clip，或 Blend Tree，或子状态机 |
| **Sub-State Machine** | 把一组状态收进盒子，降复杂度 |

状态上可调：Speed、Motion（Clip/BlendTree）、Mirror、是否写根运动掩码等。

### 3.2 默认状态与切换思维

默认状态一般是 **Idle**。  
玩法驱动模型：**逻辑设参数 → Transition 条件满足 → 切到对应状态**。  
不要指望在 Update 里 `Play("Attack")` 硬切覆盖一切——可以，但会绕开 Transition 与打断规则，团队协作时难维护；战斗里偶发强制切可用 `Play`/`CrossFade`，日常移动仍推荐参数 + Transition。

### 3.3 子状态机

例如 `Locomotion`（Idle/Walk/Run）与 `Combat`（Attack1/2）分开。  
从父图进入子状态机、再从 Exit 回到父图，适合技能段多的角色。入门先单层跑通，再拆。

## 4. 参数（Parameters）

Animator 窗口左侧 Parameters：

| 类型 | 用途 | 脚本 API |
|------|------|----------|
| **Float** | 速度、方向混合 | `SetFloat` |
| **Int** | 武器索引、阶段 | `SetInteger` |
| **Bool** | IsGrounded、IsAiming | `SetBool` |
| **Trigger** | 一次性脉冲：Jump、Attack、Hit | `SetTrigger` / `ResetTrigger` |

### 4.1 Trigger 特性（常考）

Trigger 被消费一次后自动复位。若在「还没走到用该 Trigger 的 Transition」之前多次 `SetTrigger`，可能叠状态导致异常；切场景或打断技能时常用 `ResetTrigger` 清掉残留。

### 4.2 与脚本同步示例

```csharp
using UnityEngine;

[RequireComponent(typeof(Animator))]
public class PlayerAnimDriver : MonoBehaviour
{
    static readonly int SpeedHash = Animator.StringToHash("Speed");
    static readonly int GroundedHash = Animator.StringToHash("IsGrounded");
    static readonly int AttackHash = Animator.StringToHash("Attack");

    [SerializeField] float _dampTime = 0.1f;
    Animator _anim;

    void Awake() => _anim = GetComponent<Animator>();

    void Update()
    {
        // 水平速度大小 → Float，带阻尼更平滑
        float speed = new Vector3(Input.GetAxis("Horizontal"), 0f, Input.GetAxis("Vertical")).magnitude;
        _anim.SetFloat(SpeedHash, speed, _dampTime, Time.deltaTime);

        // 落地布尔由 Motor 提供更佳；此处示意
        // _anim.SetBool(GroundedHash, motor.IsGrounded);
    }

    public void TriggerAttack() => _anim.SetTrigger(AttackHash);
}
```

**StringToHash**：避免每帧字符串查找；参数名改了要同步改 Hash 或常量。

`SetFloat(name, value, dampTime, deltaTime)` 带阻尼，适合摇杆速度，避免动画突变。

## 5. Transition（过渡）

选中两状态之间的箭头，Inspector 配置条件与混合。

### 5.1 关键字段

| 字段 | 含义 |
|------|------|
| **Has Exit Time** | 是否等当前 Clip 播到 Exit Time 比例才能切 |
| **Exit Time** | 归一化时间（0~1），如 0.8 表示接近结尾才允许 |
| **Fixed Duration** | 过渡时长用秒还是归一化 |
| **Transition Duration** | 交叉淡入淡出长度 |
| **Interruption Source** | 过渡可否被打断 |
| **Ordered Interruption** | 打断优先级相关 |
| **Conditions** | 参数条件列表（AND） |

### 5.2 设计直觉

| 场景 | 常见配法 |
|------|----------|
| Idle ↔ Walk | 无 Exit Time；条件 `Speed > 0.1` / `< 0.1`；短 Duration |
| Walk → Attack | 可无 Exit Time + Trigger，立刻举手；或带短 Exit Time 防脚滑 |
| Attack → Idle | **Has Exit Time**，让攻击大体播完；可加 Early exit 条件（被打断） |
| Any State → Hit | Trigger + 较短过渡；注意从 Hit 回来的路径要完备 |

**Has Exit Time + 无条件**：播完自动下一段（表演向）。  
**仅条件、无 Exit Time**：可立即响应输入（玩法向）。  
两者叠加：既要条件满足，又要过了 Exit Time。

### 5.3 多条件

同一 Transition 上多个 Condition 为 **AND**。OR 需要多条 Transition，或在脚本里合并成一个 Bool/Trigger。

### 5.4 过渡「卡死」排查

- 条件永远达不到（阈值不对、Trigger 被清掉）  
- Exit Time 太晚 + 又被别的高优先级 Any State 抢走  
- 忘了从攻击态连回 Locomotion  
- 层权重大、掩码导致「看起来没切」其实骨骼被别层盖住（P4.4）

## 6. Blend Tree（混合树）

一个状态里不播单一 Clip，而是按参数 **混合多个 Clip**。

### 6.1 常见类型

| 类型 | 用途 |
|------|------|
| **1D** | 一个 Float：如 Speed 0=Idle，0.5=Walk，1=Run |
| **2D Simple/Freeform Directional** | 两个 Float：如 VelocityX / VelocityZ 做 Strafe |
| **2D Freeform Cartesian** | 笛卡尔平面采样 |
| Direct | 多个权重直接由参数驱动（高级） |

### 6.2 1D 移动混合（最常用）

1. 状态 Motion 选 Blend Tree  
2. Blend Type = 1D，Parameter = `Speed`  
3. 加入 Idle / Walk / Run 三个 Clip，Threshold 分别 0 / 0.5 / 1（按手感调）  
4. 脚本连续 `SetFloat("Speed", ...)`  

比 Idle↔Walk↔Run 三条 Transition 更丝滑，少状态爆炸。

### 6.3 2D Strafe 示意

参数 `VelX`、`VelZ`（相对角色或相机的水平速度分量），在平面上摆：

- 前、后、左、右、以及斜向 Clip  

需动画资源齐套；没有侧移动画时强上 2D 会脚滑。

### 6.4 混合与脚滑

Blend Tree 只做姿势混合，**不自动解决脚步匹配**。脚滑常见原因：

- 混合权重变化快  
- 位移由脚本驱动、动画也带位移（Root Motion 重复或抵消）  
- Clip 本身步距与实际 `speed` 不一致 → 调动画速度、用 Root Motion、或动画速度匹配逻辑速度

## 7. 层（Layers）基础（衔接到 P4.4）

Animator 可多层：Base 播全身，上层用 **Avatar Mask** 只播上半身（开枪时腿仍走）。  
层权重 0~1；Blending 分 Override / Additive。  
细节（Mask 制作、Addtive 瞄准）放在 **P4.4**；本节只需知道：复杂角色很少单层搞定。

## 8. 脚本侧常用 API 进阶

```csharp
// 强制切到状态（绕过部分 Transition 逻辑，慎用）
_anim.Play("Base Layer.Attack", 0, 0f);
_anim.CrossFade("Attack", 0.1f, 0, 0f);

// 查询
float t = _anim.GetCurrentAnimatorStateInfo(0).normalizedTime;
bool inAttack = _anim.GetCurrentAnimatorStateInfo(0).IsName("Attack");
bool transitioning = _anim.IsInTransition(0);

// 动画速度（减速、子弹时间）
_anim.speed = 1f;
```

**StateMachineBehaviour**：挂在某个 State 上的脚本，进入/退出/更新时回调，适合「进入攻击态时开火框启用」。保持薄逻辑，权威伤害判定仍建议在战斗系统。

```csharp
using UnityEngine;

public class AttackStateBehaviour : StateMachineBehaviour
{
    public override void OnStateEnter(Animator animator, AnimatorStateInfo stateInfo, int layerIndex)
    {
        // animator.GetComponent<HitBox>()?.Enable();
    }

    public override void OnStateExit(Animator animator, AnimatorStateInfo stateInfo, int layerIndex)
    {
        // animator.GetComponent<HitBox>()?.Disable();
    }
}
```

## 9. 推荐的基础状态图（第三人称移动 + 攻击）

```text
Parameters: Speed(float), IsGrounded(bool), Attack(trigger), Jump(trigger)

[Base Layer]
Any State -- Jump(trigger) --> Jump
Any State -- Attack(trigger) --> Attack   // 可改为仅从 Locomotion 进，减少失控

Locomotion (Blend Tree 1D on Speed: Idle/Walk/Run)
  ↔ Jump（落地 IsGrounded==true 回 Locomotion，Has Exit Time 视情况）
  → Attack（Attack trigger，无 Exit Time）
Attack → Locomotion（Has Exit Time ≈ 0.9，或加「可取消」Bool）
```

原则：

- 移动用 Blend Tree，少切状态  
- 一次性动作用 Trigger + 明确回到 Locomotion 的边  
- Any State 只留给真正「全局可打断」的事

## 10. 与角色控制的衔接（P3.4）

| 逻辑侧 | 动画侧 |
|--------|--------|
| 水平速率 | `Speed` Float → Blend Tree |
| 是否落地 | `IsGrounded` Bool → 落地/下落状态 |
| 按下跳 | `Jump` Trigger |
| 攻击输入 | `Attack` Trigger |
| 根运动开 | 少用脚本位移或仅做补正 |
| 根运动关 | 脚本 `Move`，动画偏原地跑 |

相机相对移动时，把速度投影到角色朝向再喂给 Strafe 参数，避免「侧移却播向前跑」。

## 常见误区

- 只拖 Clip 到物体上，没有理解 Controller 状态机，一复杂就乱  
- 所有切换都走 Any State + Trigger，状态图无法推理  
- Float 用阈值跳变却不用 damp，动画爆闪  
- Trigger 残留导致进一次攻击后行为怪异，却不 `ResetTrigger`  
- Exit Time 与「可取消技能」需求矛盾未设计 Early Exit  
- 脚本 `transform` 位移 + Apply Root Motion 双驱动脚滑  
- 参数名拼写与脚本不一致（建议 Hash + 常量）  
- 在 `Cull Completely` 下仍假设镜头外单位在推进攻击判定  
- Animation Event 函数丢了或挂错物体，静默不调用

## 面试题

### Q1. Animation Clip、Animator Controller、Animator 组件三者分别负责什么？
**参考答案：**  
**Clip** 是动画数据（某段时间的曲线/骨骼采样）。**Controller** 是状态机资产，描述状态、过渡条件、混合树与层。**Animator** 是挂在 GameObject 上的运行时组件，引用 Controller（及 Avatar），通过参数与 API 真正播放。新做角色动画以 Animator 管线为主，旧 `Animation` 组件多为遗留。

### Q2. Animator 参数里 Bool 和 Trigger 有什么区别？Trigger 使用要注意什么？
**参考答案：**  
Bool 保持真/假直到被改写，适合 IsGrounded、IsAiming。Trigger 是一次性脉冲，被 Transition 消费后复位，适合 Attack、Jump、Hit。注意：触发过早或未匹配到 Transition 可能「挂起」；打断或切场景时应 `ResetTrigger` 清残留；避免同一帧无序多次 SetTrigger 导致难复现 bug。

### Q3. Transition 的 Has Exit Time 与 Conditions 如何配合？举例说明。
**参考答案：**  
仅 Conditions、无 Exit Time：条件一满足立即混切，适合移动起步、快速受击。Has Exit Time：至少等到当前动画播到指定比例，适合攻击后摇结束回 Idle。两者都开则「时间到了且条件满足」才切。攻击可取消时，常另做一条无 Exit Time、带 Cancel 条件的 Transition。

### Q4. 什么是 Blend Tree？为什么移动常用 1D Blend Tree 而不是 Idle/Walk/Run 多个 State硬切？
**参考答案：**  
Blend Tree 在一个状态内按参数对多个 Clip 做权重混合。1D 常用 Speed：连续摇杆值在 Idle–Walk–Run 间插值，过渡更平滑，状态节点更少。多 State 硬切依赖阈值 Threshold，容易在边界抖动，需更多 Transition 与阻尼逻辑。2D Blend Tree 适合八向 Strafe，但依赖侧移动画资源。

### Q5. 脚本里 `SetFloat` 的 dampTime 有什么用？为什么推荐 `Animator.StringToHash`？
**参考答案：**  
`SetFloat(id, value, dampTime, deltaTime)` 对参数做平滑跟随，避免输入噪声造成动画抖动。`StringToHash` 把参数名预转为 int，避免每帧字符串匹配，利于性能与避免魔法字符串散落；改名时集中维护常量即可。

### Q6. `Animator.Play` / `CrossFade` 与纯 Transition 驱动如何选型？
**参考答案：**  
Transition + 参数：可维护、可可视化、适合日常移动与常规技能流。`Play`/`CrossFade`：强制跳转，适合受击硬直、开场强制姿势、调试，但易绕过图上规则导致状态不一致。项目应约定主路径走状态机，强制跳转仅限少数用例，并处理返回路径。

### Q7. 动画脚滑可能由哪些原因造成？如何从管线角度排查？
**参考答案：**  
常见：脚本位移与 Root Motion 重复或冲突；Blend 权重剧变；Clip 步频与实际移速不匹配；导入压缩过猛；坡面/落地预测与动画不符。排查：先关 Root Motion 看纯脚本；再对比单 Clip 原地是否脚滑；检查 Speed 参数与动画 Speed；看 Transition Duration；最后查层 Mask 是否盖错骨骼。
