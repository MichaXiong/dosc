# P3.5 摄像机控制

> 阶段 P3 · 第三人称/第一人称机位、跟拍时机、防穿墙，以及 Cinemachine 的基本模型。

## 概念与定位

相机解决：跟着谁、往哪看、如何转视角、如何避免穿墙。  
角色位移在 `Update`，**跟拍放 `LateUpdate`**，避免慢一帧与抖动。

第三人称不要把主相机简单挂成角色子物体吃满父旋转；常用 **Pivot（yaw/pitch）+ 臂长距离 + 朝向兴趣点**。

---

## 第三人称（基础）

```text
CameraPivot（位置跟角色，鼠标转 yaw/pitch）
└── 理想点在 local (0,0,-distance)
    └── Camera（可再做碰撞缩短）
```

```csharp
void LateUpdate()
{
    _yaw += Input.GetAxis("Mouse X") * sensX;
    _pitch = Mathf.Clamp(_pitch - Input.GetAxis("Mouse Y") * sensY, minP, maxP);

    Quaternion rot = Quaternion.Euler(_pitch, _yaw, 0f);
    Vector3 pivot = target.position + pivotOffset;
    Vector3 desired = pivot + rot * (Vector3.back * distance);

    // 防穿墙
    if (Physics.SphereCast(pivot, radius, (desired - pivot).normalized,
            out RaycastHit hit, distance, mask, QueryTriggerInteraction.Ignore))
        desired = pivot + (desired - pivot).normalized * Mathf.Max(0.2f, hit.distance - radius);

    transform.position = Vector3.Lerp(transform.position, desired, 1f - Mathf.Exp(-smooth * Time.deltaTime));
    transform.rotation = Quaternion.LookRotation(pivot - transform.position);
}
```

角色相对镜头移动时，使用相机 **水平** forward/right（抹平 Y）。

## 第一人称（基础）

身体转 Y，相机本地转 X 并 Clamp（约 -85°～85°）。眼睛位置即机位，一般不做跟随插值；注意近裁剪与持械模型穿透。

## Cinemachine（常用进阶入口）

| 概念 | 作用 |
|------|------|
| Brain | 挂在主相机，混合/切换 Virtual Camera |
| Virtual Camera | 描述机位，自己不渲染 |
| Follow / Look At | 跟随与注视目标 |
| Body / Aim | 跟随算法与朝向算法 |
| Priority | 多机位谁生效 |

适合快速肩视、过场、多机位切换；与手写脚本不要同时抢主相机 `transform`。震屏可用 Impulse Source + Listener。组件名随 Cinemachine 2.x/3.x 略有差异，概念通用。

---

## 碰撞、边界与平滑（进阶）

- 手写：Pivot→相机方向 SphereCast；Mask 排除自身  
- CM：Deoccluder/Collider 类扩展  
- 地图边界：`Bounds` 夹紧或出界切安全机位  
- 平滑用 `Exp` 衰减 Lerp 或 `SmoothDamp`，避免每帧固定 `0.1` 受帧率影响  

---

## 常见误区

- Update 跟拍导致抖动  
- SphereCast 打到自己角色  
- Pitch 不限制翻到腹下  
- 多 Audio Listener  
- Brain 与手写同时驱动主相机

## 面试题

### Q1. 为什么第三人称相机跟拍通常放在 LateUpdate，而不是 Update？
**参考答案：**  
角色位移一般在 `Update`（或物理在 `FixedUpdate`）里完成。`LateUpdate` 在同一帧所有 `Update` 之后执行，相机再读取角色最终位置，可避免「相机先更新、角色后移动」造成的慢一帧或抖动。若跟拍与移动都挤在 `Update` 且执行顺序未保证，就容易出现拉扯感。

### Q2. 手写第三人称时，为什么不建议把主相机直接挂成角色子物体？Pivot 分层解决什么问题？
**参考答案：**  
子物体会完全继承父物体旋转：角色转向、抬头动画、根运动都会直接拧相机，穿模与仰俯也难控。常见做法是 **Pivot** 只负责鼠标 yaw/pitch，再在后方臂长处放相机看向兴趣点；Pivot 位置跟角色（或脚本同步），旋转与角色移动解耦，碰撞拉近也只改臂长，不破坏角色本身 Transform。

### Q3. 如何用射线/球检测防止相机穿墙？Mask 要注意什么？
**参考答案：**  
从 Pivot（或观察点）向理想相机位置做 `SphereCast`/`Raycast`，若命中障碍，把相机停在命中点前（距离减去半径）。**Mask 应排除角色自身与触发器**，否则会打到自己的胶囊导致相机贴脸；障碍用独立 Layer，查询时 `QueryTriggerInteraction.Ignore` 避免触发器误挡。

### Q4. Cinemachine 里 Brain、Virtual Camera、Priority 分别是什么关系？
**参考答案：**  
**Virtual Camera** 只描述「期望机位」（Follow/Look At、Body/Aim 等），自己不渲染。**Brain** 挂在主相机上，按规则选用/混合 VCam，真正驱动主相机。**Priority** 数值高的 VCam 优先生效，常用于过场、瞄准、死亡机位切换，而不用手动改主相机 Transform。手写脚本与 Brain 不要同时抢主相机。

### Q5. 第一人称视角如何分配 yaw / pitch？有什么限制？
**参考答案：**  
左右看（yaw）转**身体/根节点**水平旋转；上下看（pitch）只转**相机本地** X 轴，并用角度 Clamp（如 -85°～85°）防止翻转。这样移动方向与视线水平分量一致，又不会出现相机翻到肚子底下。同时注意 Near Clip 与武器模型穿插。

### Q6. 相机位置平滑为什么不建议每帧 `Lerp(a, b, 0.1)`？
**参考答案：**  
固定 `t=0.1` 依赖帧率：帧率高跟得快、帧率低跟得慢，手感不稳定。更稳的是与时间相关的平滑，例如 `t = 1 - exp(-k * deltaTime)` 再 Lerp，或使用 `Vector3.SmoothDamp`。旋转同理用 `Slerp`/`RotateTowards` 并结合 `deltaTime`。
